Arquitectura

Backend

Laravel 12, PHP 8.2+, rutas web y API, controladores, middleware, Eloquent y vistas Blade. La entrada HTTP es public/index.php.

Canales

El portal Blade usa sesión web. La app Android, empaquetada con Capacitor, consume /api/mobile/* por HTTPS y Bearer token Sanctum; no mantiene una base clínica local.

Datos y tareas

La configuración de producción usa MySQL. Laravel consulta la base y el Scheduler ejecuta comandos; Laravel solicita a Firebase Cloud Messaging (FCM) el envío push.

La web pública presenta información del consultorio, ofertas, solicitudes, disponibilidad y enlaces de contacto/WhatsApp. No se documenta un proveedor externo de WhatsApp: la aplicación prepara enlaces/mensajes para que la persona o el personal los abra. La app requiere internet para consultar datos.

Módulos

Autenticación y recuperación

Inicio y cierre de sesión, perfil, solicitud de restablecimiento y cambio por token de Laravel Password Broker. La ruta de solicitud limita tráfico a 3 intentos por minuto y entrega respuesta genérica para no enumerar correos.

Pacientes y cuentas

El personal registra expediente; al crear una cuenta de paciente se asigna role_id 3. La gestión de usuario/contraseña temporal de pacientes está limitada al administrador. El asistente no puede acceder a esas rutas.

Solicitudes y agenda

El formulario público crea solicitudes, no citas inmediatas. Al confirmar se vuelve a validar disponibilidad, se crea cuenta y paciente y se inserta una cita confirmada; el rechazo cancela la solicitud. Las citas manuales nuevas empiezan en espera.

Casos y seguimiento

Un caso corresponde a un expediente y puede tener citas asociadas; cada cita puede opcionalmente pertenecer a un caso. El panel del paciente muestra progreso y citas realizadas asociadas.

Contenido y consultorio

Ofertas activas se muestran en web pública y panel de paciente. La fila de office_settings guarda nombre, dirección, URL de mapa y WhatsApp; el administrador puede editarla y el frontend deriva mapa incrustado desde la dirección.

Reportes

Resumen de citas, pacientes, casos, servicios e importes estimados; los estados mostrados deben mantenerse en sincronía con el enum de citas.

Asistente del portal público

El widget permite usar opciones rápidas o escribir una pregunta de hasta 500 caracteres. Una clasificación básica en el servidor reconoce temas como servicios/precios, ofertas, horario, ubicación, citas y contacto; las respuestas se construyen con datos públicos actuales del consultorio. Los mensajes no se guardan.

Sin proveedor de IA

No consulta expedientes, pacientes o citas ni envía conversaciones a servicios externos. La clasificación de palabras clave puede no entender preguntas ambiguas; en ese caso muestra opciones generales. WhatsApp solo se abre si la persona lo elige.

Alcance

No diagnostica ni recomienda tratamientos o medicamentos. Si detecta síntomas o urgencia deriva al consultorio/servicios de emergencia; no sustituye una valoración profesional.

Protección

El endpoint valida la longitud e intención, usa CSRF de Laravel y limita solicitudes a 20 por minuto. Evita compartir datos personales o información clínica identificable.

Para ajustar la clasificación, revisa app/Support/ChatbotMessageClassifier.php; para respuestas, app/Http/Controllers/ChatbotController.php; para el widget, resources/views/home.blade.php.

Modelo de datos

Consulta el diagrama interactivo completo. Las migraciones versionadas definen 15 tablas de aplicación y soporte: roles, usuarios, pacientes, servicios, solicitudes_citas, citas, casos_clinicos, horarios_bloqueados, ofertas, office_settings, password_reset_tokens, personal_access_tokens, push_devices, cache y cache_locks. La tabla de control migrations que Laravel mantiene no se cuenta como entidad del dominio.

Las claves foráneas declaradas son: usuarios.role_id → roles.id; citas.paciente_id → pacientes.id; citas.servicio_id → servicios.id; citas.caso_clinico_id → casos_clinicos.id (nullable, ON DELETE SET NULL); casos_clinicos.paciente_id → pacientes.id; horarios_bloqueados.usuario_id → usuarios.id (nullable, ON DELETE SET NULL); y push_devices.user_id → usuarios.id (ON DELETE CASCADE). Las citas y casos se eliminan en cascada al borrar paciente; las citas también al borrar servicio.

pacientes.user_id es nullable y se usa en Eloquent, pero la migración no define FK ni índice. personal_access_tokens usa morphs (tipo/id con índice, sin FK directa). Solicitudes, ofertas, configuración, recuperación y tablas de caché no declaran FK. La migración de recordatorios añade citas.reminder_sent_at y el índice compuesto estado/fecha/reminder_sent_at.

Configuración

Variables de entorno de referencia

.env.example no contiene secretos. Define APP_KEY, APP_URL y credenciales de base de datos en el panel privado del hosting, nunca en GitHub. Producción debe usar APP_ENV=production, APP_DEBUG=false y HTTPS. La configuración de producción conocida de Dentissa usa MySQL; localmente puede configurarse SQLite para pruebas si está instalado su controlador PDO.

.env.example fija SESSION_DRIVER=file, CACHE_STORE=file y QUEUE_CONNECTION=sync. Sin embargo, config/cache.php usa database como valor por defecto si CACHE_STORE no se define. Las migraciones del repositorio sí crean cache y cache_locks; configura el store de forma explícita para evitar discrepancias entre hosting y .env.

Para push se requieren FIREBASE_PROJECT_ID y el secreto FIREBASE_SERVICE_ACCOUNT_JSON en backend; para el enlace público de descarga se admite ANDROID_APP_DOWNLOAD_URL. Nunca incluyas la clave privada Firebase en Android ni Git.

Correo de recuperación

MAIL_MAILER=log no envía correo real. Usa proveedor transaccional SMTP y dominio verificado (SPF/DKIM/DMARC); el controlador bloquea reset en producción si se mantiene log, para no exponer enlaces en logs.

Almacenamiento y datos locales

La app Android empaqueta la interfaz, pero no una base de datos offline: requiere conexión HTTPS al backend. Los archivos Laravel privados usan almacenamiento local. Si se agregan imágenes clínicas, valida privacidad, backups y permisos; no publiques documentos sensibles mediante el disco public.

Despliegue en Laravel Cloud

  1. Despliega el backend Laravel y configura PHP, variables privadas, APP_KEY, URL HTTPS y conexión MySQL.
  2. Construye frontend con el flujo de build del proyecto; para Android usa DENTISSA_API_URL=https://dominio npm run android:sync antes de compilar el APK.
  3. Aplica migraciones pendientes con php artisan migrate --force; revisa php artisan migrate:status. Esto crea también tablas Sanctum, caché y push si no estaban instaladas.
  4. Configura Firebase en servidor con FIREBASE_PROJECT_ID y el JSON de cuenta de servicio como secreto privado.
  5. Activa Scheduler en el App cluster. citas:enviar-recordatorios se ejecuta cada minuto, con onOneServer y withoutOverlapping; citas:actualizar-vencidas corre diariamente.
  6. Verifica la lista con php artisan schedule:list, observa logs, revisa HTTPS, APP_DEBUG=false y prepara respaldos probados de base de datos.
  7. Para enlaces de descarga configura ANDROID_APP_DOWNLOAD_URL con una URL HTTPS pública de un APK firmado; no publiques keystores.

Hallazgos a revisar

Esquema

Estados de caso clínico: la migración permite solo activo y finalizado. En actualización, el controlador acepta activo, pausado y completado; en creación valida estado solo como string opcional. El modelo declara además suspendido. Alinear validación, modelo y enum antes de guardar estados adicionales en MySQL estricto.

Relación

Vínculo usuario-paciente: pacientes.user_id es nullable pero carece de FK e índice. La aplicación depende de ese vínculo para asociar perfiles y limitar datos; evaluar constraint e índice después de depurar huérfanos y duplicados.

Autorización

Dashboard administrativo: /dashboard/admin está dentro de autenticación, pero no tiene middleware admin y AdminController::index no comprueba el rol. Por tanto, cualquier usuario autenticado puede intentar cargar el resumen administrativo; restringe la ruta en el backend antes de usarla con datos reales. El mismo grupo de rutas no limita explícitamente /dashboard/asistente al rol asistente. Ocultar enlaces del menú no es autorización.

Relaciones Eloquent

User::citas() y User::casosClinicos() apuntan a user_id, columna que no existe en citas ni casos_clinicos. No se encontraron llamadas actuales en controladores; corregir o retirar esas relaciones antes de usarlas.

Agenda

La disponibilidad se vuelve a comprobar al confirmar, y solicitudes/citas usan transacciones en algunos flujos, pero citas no tiene unique(fecha,hora). La base de datos no garantiza por sí sola exclusividad ante dos reservas concurrentes.

Diferencias de despliegue

El diagrama se deriva de las migraciones versionadas del repositorio, no inspecciona directamente la base viva de Laravel Cloud. Comprueba migrate:status, configuración de CACHE_STORE y que producción haya aplicado las migraciones de Sanctum, recordatorios, push y caché.

Validación

Los tests feature requieren la extensión PDO de SQLite cuando usan la configuración de pruebas en memoria. Si no está instalada, PHPUnit falla antes de ejecutar assertions; ejecuta los tests en CI o en un entorno con pdo_sqlite.
