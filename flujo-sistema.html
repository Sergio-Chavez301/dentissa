Flujo del sistema y reglas de negocio

Este documento resume cómo funciona la clínica: roles, pacientes, solicitudes, citas, casos clínicos, usuarios del sistema y la relación entre cada uno.

Roles
  • Administrador: gestiona usuarios, pacientes, citas, casos, servicios, solicitudes y reportes.
  • Asistente: revisa y gestiona citas, pacientes, casos y agenda.
  • Paciente: accede al portal personal para ver sus citas y casos.
Regla principal
  • Un paciente puede tener un usuario del sistema.
  • Un usuario del sistema puede tener un rol.
  • Una cita siempre pertenece a un paciente.
  • Un caso clínico siempre pertenece a un paciente.
Datos clave
  • El usuario del paciente se crea con role_id = 3.
  • La contraseña inicial suele ser temporal y luego se cambia.
  • El horario debe estar disponible para agendar una cita.

Flujo principal del sistema

1
Solicitante entra al sitio público
Completa el formulario de cita desde la web pública. Eso crea una solicitud, no una cita directa.
2
Admin o asistente revisa la solicitud
Se valida si el horario sigue disponible. Después puede confirmar o rechazar la solicitud.
3
Si confirma, se crea al paciente
Se genera su usuario del sistema, contraseña temporal y relación con el paciente.
4
Se crea la cita
La cita queda asociada al paciente y al servicio elegido.
5
Se abre el caso clínico
El paciente ya tiene ficha, y el administrador puede crear un caso clínico con tratamiento base y progreso.
6
El paciente entra al portal
Inicia sesión con su usuario y puede ver sus citas, caso clínico y perfil.

Cómo funciona cada módulo

Módulo Qué hace Regla importante
Registro de pacientes Crea la ficha del paciente y su cuenta de acceso. Si no existe un usuario, se crea uno nuevo con rol paciente.
Solicitud de cita pública Recibe una intención de cita del visitante. No crea la cita final hasta que la confirme el administrador.
Registro de citas Agrega la cita con servicio, fecha y hora. La hora debe estar libre y el formato debe ser válido.
Pacientes Gestiona los datos del paciente, historial y acceso. Todo paciente puede estar asociado a un usuario.
Casos clínicos Registra el tratamiento base y el avance del paciente. Debe estar asociado a un paciente existente o recién creado.
Regla clave cuando no existe paciente: no se bloquea el sistema. El administrador puede crear al paciente al mismo tiempo que crea la cita o el caso clínico.

Cuando registras una cita pero no hay pacientes

  • Se activa la opción “Registrar nuevo paciente para esta cita”.
  • Se llena nombre, apellidos, correo, teléfono y fecha de nacimiento.
  • El sistema genera automáticamente:
    • usuario con rol paciente
    • paciente registrado
    • cita asociada a ese paciente

Cómo se registra el paciente y el usuario al mismo tiempo

  1. El admin llena los datos del paciente.
  2. El backend genera un username automático.
  3. Se genera una contraseña temporal aleatoria.
  4. Se crea el registro en la tabla usuarios con role_id = 3.
  5. Se crea el registro en la tabla pacientes con user_id vinculado.
  6. La sesión muestra las credenciales para que el paciente pueda entrar al sistema.

Relación de entidades

  • Usuario → tiene rol
  • Paciente → tiene usuario y muchas citas
  • Cita → pertenece a un paciente y un servicio
  • Caso Clínico → pertenece a un paciente
  • Solicitud → es una petición pública antes de confirmar cita

Credenciales temporales del paciente

Cuando se crea un paciente nuevo desde cualquier flujo del sistema, también se crea su acceso al portal con un usuario y una contraseña temporal.

  • Se genera un username automático con base en el nombre y apellidos.
  • Se genera una contraseña temporal aleatoria de varios caracteres.
  • La contraseña se guarda hash en la base de datos, no en texto plano.
  • El administrador o asistente ve estas credenciales en la ficha del paciente y puede enviarlas por WhatsApp.
  • El paciente entra a /login con su usuario y esa contraseña temporal.
Importante: la contraseña temporal sirve solo para que el paciente entre por primera vez. Después debe cambiarla por una real.
A
Creación del acceso
El sistema crea el usuario con rol paciente y lo vincula al paciente mediante user_id.
B
Primer ingreso
El paciente entra a la vista de login con su nombre de usuario y contraseña temporal.
C
Cambio de contraseña
El paciente puede cambiarla desde la opción de perfil o usando el flujo de recuperación de contraseña por email.

En el código, esto ocurre con los controladores de pacientes y autenticación: PatientController genera la contraseña temporal y AuthController valida el login y redirige según el rol.

Reglas de negocio resumidas

  • El paciente debe ser registrado antes de generar historial médico o citas.
  • La cita ya no puede estar en horario ocupado.
  • La solicitud pública no reemplaza la cita final.
  • Un caso clínico siempre debe tener un paciente asociado.
  • Si no existe el usuario del paciente, se crea automáticamente.
  • El perfil del paciente es la cartera médica del sistema.
  • La contraseña temporal es solo de acceso inicial; después debe cambiarse para quedar la contraseña definitiva.
